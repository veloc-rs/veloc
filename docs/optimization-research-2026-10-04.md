# 优化研究与 K230 实测

日期：2026-10-04。对象：当前工作树，包含此前尚未提交的架构改动。

最初目标是 CoreMark 运行性能超过 LLVM 20%，同时缩短编译时间。这个目标需要
独立测量运行性能和编译时间，不能用更少的 IR 指令或更多成功匹配来代替。
第一阶段实现了通用优化与编译开销改进，尚未达到运行性能目标。
后续用户将目标调整为超过 LLVM 5%；本页末尾记录继续实施的状态机分支贯穿。
完整配置、最终样本和复现方法见 [测量记录](../crates/veloc-c/benchmarks/coremark/RESULTS.md)。

## 研究依据

| 工作 | 相关结论与本轮取舍 |

| [RAPO，LCTES 2026](https://pldi26.sigplan.org/details/LCTES-2026-main/7/RAPO-Retrieval-Augmented-Phase-Ordering) | 将寻找 pass 顺序的工作放到离线，在线检索已找到的策略。其主要评估指标是 IR 指令数，不能直接外推 CoreMark 跑分。本轮先建立可测的固定流程和无修改结果复用，没有引入训练模型或在线搜索。 |

| [Lazy SCCP，MPLR 2024](https://conf.researchr.org/details/issta-ecoop-2024/mplr-2024/6/Lazy-Sparse-Conditional-Constant-Propagation-in-the-Sea-of-Nodes) | 讨论 Sea of Nodes 上的惰性 SCCP。当前 MIR 是块 SSA，因此采用经典的值事实和可执行控制流联合求解，没有照搬 Sea of Nodes 算法。 |
| [Relational E-matching，POPL 2022](https://ztatlock.net/pubs/2022-popl-rematch/2022-popl-rematch.pdf) | 把匹配看成关系查询，减少重复枚举和延迟过滤。本轮实现检查前推、重叠查询合并和关系行去重；尚未实现论文的完整关系优化器或最坏情况最优连接算法。 |

这些工作支持先减少无效计算、明确依赖，再考虑昂贵搜索的方向。
它们并不证明新增 pass 一定改善这台 CPU 上的运行性能。

## 已实施

### SCCP

`SccpPass` 同时求解值和可执行控制流，值格为未获知、常量、变化值。
只有可执行边的参数才参与块参数的合并。值发生变化时，仅把可执行块里的
SSA 使用者加入队列；不反复扫描整个函数。格单调变化，求解不依赖轮数预算。

求解期间不编辑 IR。收敛后替换常量、折叠已证明的分支、删除不可达块。
`Select` 只在选中的输入上取事实，变化条件则合并两个输入。运算求值与
Simplify/e-graph 共用语义和折叠入口，不能求值的指令保守处理。
只有成功求值能够证明的计算才被删除，常量结果不能自行证明其他操作不陷阱。

SCCP 位于内联后和内存提升后，处理两个不同的事实来源。
后一次调用若没有新的 IR 修改且前一次没有修改，会由管理器跳过。
消融实验移除了内联前额外的一次 SCCP，五个 CoreMark 对象文件及最终 ELF
逐字节相同，因此默认流程没有保留那次提前遍历。

### 支配作用域内的谓词传播

`PredicatePass` 在条件分支的唯一前驱后继中建立事实，并沿支配树传播。
离开子树时撤销事实，使用显式工作栈避免深 CFG 的递归。
它传播条件真值、相等常量，以及相同操作数对之间的整数比较蕴含关系。
有符号和无符号次序不混用；入口块、相同分支目标和多前驱合流保持保守。

这不是完整区间分析，也不克隆基本块。它产生的局部机会由后续 Simplify/CFG
清理消费。比较蕴含逻辑由 `IntCC::implies` 提供，CFG 分支贯穿共用该入口。

### 减少 pass 重跑

函数 pass 可以显式提供复用键，声明相同配置下同键实例的行为一致。
管理器只缓存 **Unchanged** 结果；任意 pass 报告 Changed 或遇到模块 pass
边界都会清空缓存。未显式参与的 pass 每次照常执行。

没有把一次 Changed 当作到达不动点，也没有把 pass 名称当作配置身份。
该机制目前只能省掉没有任何中间修改的重复运行。进一步按修改类型选择性
重跑，需要编辑接口提供可靠摘要，并让每个 pass 声明实际依赖，不能只添加标记。

### e-graph 查询

- 查询编译器按绑定依赖前推类型、常量、重复变量及属性检查。
- 属性字面量和属性相等检查使用生成的类型化谓词；构建计划仍检查完整契约。
- 对同一根激活的重叠输入查询，用静态扫描数比较多个专用查询和一次完整查询。
  两条路径遵守相同搜索预算；静态扫描数只是估计，不是精确基数模型。
- 关系缓存按规范化操作数和属性去重。同一等价类中多个具体 SSA 定义仍保留，
  供提取阶段满足支配关系；查询无需重复枚举相同结构。
- 搜索与应用保持两个阶段，不在枚举过程中修改图。

状态机翻译单元的单次 profile 中，匹配步数从约 525,951 降到 2,136；
搜索耗时从约 89 ms 降到约 0.12 ms。该数字是局部诊断样本，不是完整编译加速比。
最大收益来自去掉重复关系行，并非减少搜索预算。

### 仿射函数分析的表示

GF(2) 多项式改为排序、唯一的单项式序列，小集合内联存储。
异或使用有序归并，乘积排序后消去偶数次项。不可变符号字共享引用，分支
复制值映射时不再深拷贝每一个多项式。识别范围、证明方式和工作上限保持一致。

`core_util.c` 的单次 profile 中，该阶段从约 29 ms 降到约 6 ms。
该优化仍按 MIR 语义识别函数，没有函数名、CRC 多项式或 CoreMark 专用入口。

## 没有采用的实验

- 把 RISC-V 小表转换为比较树的阈值从 8 降到 4：短测约 4744 分，低于
  原配置约 5030 分，已恢复。短测仅用于筛选，不作为有效 CoreMark 成绩。
- 在 CFG 后额外运行一次 Simplify：短测没有收益，已移除该额外调用。
- 没有引入在线 phase-order 搜索、ILP 提取或更大搜索预算。

## 运行性能还缺什么

采样器显示 Veloc 运行时间主要分布在矩阵（约 35%）、状态机（约 35%）和
链表（约 28%）。这些比例来自带 SIGPROF 的独立诊断可执行文件，未混入跑分。

1. **循环存储提升及别名契约。** 矩阵内层循环已把累加值放入寄存器，仍每次
   写回内存。当前 MIR 无法证明其他指针不观察该写入，不能直接移到循环外。
   下一步应先设计前端可提供、优化器可验证的别名事实或运行时版本化证明。
2. **状态机路径特化。** 对已知循环状态直接贯穿分派，可能减少重复 switch。
   可参考 [LLVM DFAJumpThreading](https://llvm.org/doxygen/DFAJumpThreading_8h_source.html)，
   需要通用 SSA 修复、代码增长成本和可更新的 CFG 分析；不能只修改 case 顺序。
3. **内联与寄存器压力。** 在链表比较及大状态机上，大小阈值不足以预测收益。
   应把循环位置、跨调用活跃值和生成代码大小纳入离线测量，再决定默认策略。

这些是由生成代码和采样推导的后续方向，尚无证据保证其中任何一项能达到 +20%。

## 第二阶段：常量状态驱动的分支贯穿

实现位于 `veloc/optimizer/src/passes/threading/`，进入所有目标共用的 MIR
优化流程。参考 [LLVM DFAJumpThreading 的设计说明](https://llvm.org/doxygen/DFAJumpThreading_8cpp_source.html)
中按已知状态绕过循环分派的思路；本实现利用 MIR 块参数传递依赖，独立实现块复制。

### 识别与变换

1. 从 `BrTable` 的选择值出发，反向遍历块参数的输入。只有完全由参数和至少
   两个字面常量组成的网络才成为候选。指令计算出的状态、函数输入等均保持
   保守，因此普通归纳变量不会触发循环展开。
2. 删除不可达块，再把跨块定义和使用通过显式块参数连接。函数输入和常量
   全局可用。复制块时只需要重映射该块的参数和局部结果，无需在复制之后
   再搜索受影响的支配关系。后续参数清理会删除这些临时传递中的恒等关系。
3. 对具有常量状态实参的入边，按 `(原块, 常量绑定)` 复用一个特化版本。
   复制过程中调用已有的类型化求值器，折叠计算与条件分支；已知选择值的
   `BrTable` 变为直接跳转。新出边进入工作队列，沿路径继续传播常量状态。
4. 单块最多 12 条指令，每函数复制成本最多为原函数指令数与 512 的较小值。
   不继续复制已生成的版本，不复制栈分配和带所有权转移契约的操作。
   超出成本时保留原路径。副作用按原路径和顺序执行，没有猜测性执行。

例如，`state = B; goto dispatch` 可以直接连到状态 B 的已特化检查路径。
检查过程中仍会执行原本需要的字符读取、边界条件和内存访问，不能因为已知
状态就跳过它们。整个变换依据 IR 数据流，不读取函数名或运行输入。

### 放置与测量

`ThreadingPass` 位于谓词传播之后、最后一组 CFG 清理之前。把已有的
`SimplifyParamsPass` 从清理末尾移到 Threading 后，先恢复 SSA 值的相同身份，
再让局部简化和 CFG 识别比较链；没有增加参数清理的执行次数。

状态机单元的一个 profile 样本中，该 pass 约 0.83 ms，共创建 178 个小块版本，
折叠 45 处分支；后续清理消除了三个热点状态分派表。最终可执行文件 `.text`
从 10,566 增至 11,030 字节（+4.39%）。矩阵、链表和工具函数单元的对象文件
与上一阶段逐字节相同。

短测仅用于选择清理顺序：初版中位数约 6040 分，提前参数清理后约 6198 分。
最终长测、编译耗时和产物身份统一记录在
[CoreMark 测量记录](../crates/veloc-c/benchmarks/coremark/RESULTS.md)。

当前识别仍限于常量驱动的分派网络；不包含任意谓词路径克隆或一般范围分析。
SSA 显式传递在整个候选函数内进行，大函数中还有按受影响区域缩小处理范围
的空间。矩阵存储提升仍需要独立的别名证明，不属于此次状态机优化。
